# 写作环境与站点功能

本文记录 2026 年 10 月对笔记站的一次集中改造，既是**改动清单**，也是**日常使用说明**。

## 一分钟上手

| 我想…… | 怎么做 |
| --- | --- |
| 边写边看排版 | 在 md 文件里按 `Ctrl+Shift+V` |
| 看和线上完全一致的效果 | 运行任务 `docs:dev`，浏览器开 `http://localhost:5173/notes/` |
| 提交前检查有没有写坏链接 | `Ctrl+Shift+B` 构建，有死链会直接报错 |

## 一、VS Code 写作环境

### 1.1 预览直接显示站点样式

站点主题样式 `docs/.vitepress/theme/style.css` 已挂到 VS Code 内置预览上，因此下面这些自定义标记**在编辑器里就能看到真实效果**，不用开浏览器：

| 写法 | 实际效果 | 用途 |
| --- | --- | --- |
| `<span class="font-jcys">文字</span>` | <span class="font-jcys">加粗 + 黑字</span> | 考点、关键词（全站已用 689 处） |
| `<span class="font-jcysxh">文字</span>` | <span class="font-jcysxh">蓝字 + 下划线</span> | 定义、术语 |
| `<span class="font-jc">文字</span>` | <span class="font-jc">仅加粗</span> | 普通强调 |
| `<span class="font-zybj">文字</span>` | <span class="font-zybj">黑字 + 下划线</span> | 备用，目前未使用 |

上面「实际效果」一列就是真实渲染结果，不是图片。类定义都在 `style.css` 里，想改颜色改那里即可。

::: tip 为什么之前做不到
`style.css` 里用了 VitePress 的内置 CSS 变量（`--vp-c-brand`、`--vp-c-bg-soft`、`--vp-c-text-code`），
而 VS Code 预览没有 `vars.css`，这些变量缺失会让样式**静默失效**。
适配文件 `vscode-preview.css` 专门补了这几个变量。
:::

### 1.2 代码片段（snippets）

在 md 文件里输入前缀后按 `Tab` 展开。**支持「先选中文字再展开」**——选中的内容会被自动包进标记里，这是最高频的用法。

| 前缀 | 展开结果 |
| --- | --- |
| `fm` | frontmatter 骨架（含 `order`） |
| `jcys` | `<span class="font-jcys">选中内容</span>` |
| `jcxh` | `<span class="font-jcysxh">选中内容</span>` |
| `jc` | `<span class="font-jc">选中内容</span>` |
| `tip` | `::: tip` 提示容器 |
| `warn` | `::: warning` 警告容器 |
| `danger` | `::: danger` 危险容器 |
| `details` | `::: details` 折叠容器 |
| `inc` | 文件包含指令（**语法有坑，见下方警告**） |
| `br` | `<br>` |

片段定义在 `.vscode/vitepress.code-snippets`，可以自己加。

::: danger 文件包含指令不能完整写进笔记里
`@include` 是在**渲染之前**对原始 Markdown 文本做全局替换的，**它不区分代码块**——
写在 ``` 围栏代码块里也好、行内代码里也好，照样会被当成真的包含指令执行。

后果：只要笔记里出现了完整的包含指令，构建时就会去读那个文件，**找不到就直接构建失败**
（本文档第一版就是这么把站点构建搞挂的）。

所以需要演示语法时，必须把它拆开写，例如：

`<!--` + `@include:` + 相对路径 + `-->`

日常使用完全不用记：输入 `inc` 按 `Tab` 就会自动展开成正确格式。
:::

### 1.3 任务

`Ctrl+Shift+B` 直接构建，或从菜单「终端 → 运行任务」里选：

| 任务 | 作用 |
| --- | --- |
| `docs:dev` | 开发服务器，改完即刷新，端口 5173 |
| `docs:build` | 完整构建（默认构建任务），**有死链会失败** |
| `docs:preview` | 用构建产物起服务器，端口 4173，最接近 GitHub Pages 的实际表现 |

### 1.4 链接校验

已开启 `markdown.validate.enabled`。写错相对路径会立刻出现波浪线提示。

- 外部 `http(s)` 链接**不会被校验**（避免误报和网络请求）
- 万一某个链接确实是故意写的不存在的路径，加进 `.vscode/settings.json` 的 `markdown.validate.ignoredLinks`

验证效果：全站 1684 条内部链接目前 **0 死链**。

### 1.5 图片粘贴

截图后直接 `Ctrl+V` 粘进 md，图片会存到**笔记同级的 `<笔记名>.assets/` 目录**，并自动插入链接。

已实测 VitePress 能正确处理这种相对路径：

- 小于 4KB 的图 → 内联成 data URI，不产生额外请求
- 大图 → 打包进 `dist/assets/`（带内容哈希）并重写链接

如果想统一放 `docs/public/images/`，然后用 `/images/xxx.png` 引用也可以（VitePress 会自动补上 `/notes/` 前缀），只是需要手动挪文件。

### 1.6 推荐扩展

打开仓库时 VS Code 会提示安装：

| 扩展 | 用途 |
| --- | --- |
| Markdown All in One | 表格格式化（本仓库有 39 个表格）、目录生成、快捷键 |
| markdownlint | 规范检查，能发现手写 HTML 时漏闭合的标签 |
| Markdown Preview Enhanced | 需要 `::: tip` 容器的预览效果时用它 |
| Code Spell Checker | 中英混排拼写检查（中文不会被判错） |

## 二、站点新增能力

### 2.1 站点图标

之前是 VitePress 默认图标，现在换成内联 SVG（📚），不产生额外网络请求。
要换图标改 `config.mjs` 里的 `FAVICON` 常量。

### 2.2 sitemap.xml

构建时自动生成，共 56 条 URL，便于搜索引擎收录。配置在 `config.mjs` 的 `sitemap.hostname`。

::: warning 有个坑
VitePress **不会**自动为 sitemap 拼接 `base`，所以 hostname 必须写成
`https://wuhaotdcq-s.github.io/notes/`，**结尾的斜杠不能少**——
少了斜杠 `/notes` 前缀会被 URL 解析吃掉，生成的链接全是错的。
:::

### 2.3 最近更新时间

每页底部显示「最近更新时间」，取自 git 提交时间。

前提是 GitHub Actions 里 `actions/checkout` 用了 `fetch-depth: 0`（已配置好），
否则浅克隆拿不到历史，这个功能会失效。

### 2.4 页面语言与标题

- `<html lang="zh-CN">`（之前是 `en`），影响屏幕阅读器、浏览器翻译提示和搜索引擎
- 浏览器标签标题格式为 `页面标题 | 笔记站`

### 2.5 品牌色真正生效

::: warning 之前是失效的
`style.css` 只覆写了 `--vp-c-brand`，但这个变量在 VitePress 2 里已被标记为 **DEPRECATED**，
全站只有 6 处引用；真正控制链接、按钮、激活项的是 `--vp-c-brand-1/2/3/soft`（43 处引用），
它们一直是默认的靛蓝色。
:::

现在已按色阶补齐，并且**亮色模式用了加深后的颜色**——因为原色 `#a6acff` 在白底上对比度只有 2.11:1，做链接色读不清。

| 变量 | 亮色 | 暗色 | 对比度 |
| --- | --- | --- | --- |
| `--vp-c-brand-1` | `#5a63d8` | `#a6acff` | 4.99:1 / 8.26:1 |
| `--vp-c-brand-2` | `#4f57c9` | `#bcc0ff` | 悬停态 |
| `--vp-c-brand-3` | `#4149b0` | `#8b91f5` | 实心按钮背景 |
| `--vp-c-brand-soft` | 半透明 | 半透明 | 提示容器背景 |

四个值都在 `style.css` 的 `:root` / `:is(.dark, .vscode-dark)` 里，想调直接改。

### 2.6 本地搜索

无需外部服务的全文搜索，按 `Ctrl+K` 唤起，界面文案已中文化。

## 三、目录约定与排序

### order 字段

侧边栏顺序由每个 md 文件 frontmatter 的 `order` 决定，**数字越小越靠前，不写则排到最后**。

```yaml
---
order: 3
---
```

目录的排序取**该目录下 `index.md` 的 `order`**。

### index.md

每个目录建议放一个 `index.md`，**没有 `index.md` 且没有其他 md 的目录不会出现在侧边栏**。

### 不用手动维护侧边栏

侧边栏和导航栏都是构建时按目录结构自动生成的：

- 侧边栏：`docs/.vitepress/sidebar.mjs`
- 导航栏：`docs/.vitepress/nav.mjs`（可用 `docs/生成导航栏.py` 重新生成）

**新建 md 文件后不需要改任何配置**，重新构建就会出现在侧边栏里。

## 四、常用命令

```bash
npm install           # 安装依赖
npm run docs:dev      # 开发服务器（会自动打开浏览器）
npm run docs:build    # 构建到 docs/.vitepress/dist
npm run docs:preview  # 预览构建产物
```

::: info 关于部署
一般**不需要**手动部署。推送到 `main` 分支会自动触发 GitHub Actions 构建并发布到 GitHub Pages，
大约 2~3 分钟完成。

`npm run deploy`（gh-pages）是备用方案，用不到可以不管。
:::

## 五、发布流程

```bash
git add -A
git commit -m "本次改动说明"
git push
```

::: warning 推送可能失败
这台机器访问 GitHub 会**间歇性连接重置**。如果报 `Recv failure: Connection was reset`，直接重试通常就好了。

长期方案有两个：挂代理，或改用 SSH over 443。
注意标准的 SSH **22 端口是被阻断的**，但 `ssh.github.com:443` 可以通。
:::

## 六、排错

### 预览里样式不对

确认 `.vscode/settings.json` 里的 `markdown.styles` 两项都还在，且路径没变。
样式文件被移动或改名后，预览会退化成 VS Code 默认外观（但站点不受影响）。

### 预览是旧内容

预览会跟随当前活动文件自动切换。如果同时开着多个 md，用
「Markdown: Toggle Preview Locking」把它锁定到指定文件。

### 构建报死链

VitePress 构建时就会检查内部链接，失败信息里有具体文件和行号。

::: warning 裸 URL 会被自动转成链接
VitePress 默认开启 `linkify`，直接写出来的网址会自动变成链接并参与死链检查。
而且 **localhost 被当作内部链接**，随手贴一个 `http://localhost:5173/...` 就会让构建失败。

写网址时用反引号包起来即可避免。
:::

如果是故意指向不存在路径的链接，加进 `markdown.validate.ignoredLinks`
**不会**让构建通过——那是 VS Code 编辑器的检查，跟构建期的检查是两套独立机制。
构建期的检查要靠 `config.mjs` 的 `ignoreDeadLinks`。

### `::: tip` 容器在 VS Code 预览里是纯文本

内置预览不认识容器语法，这是正常的。要看容器效果：

1. 用 `docs:dev` 任务在浏览器里看（推荐）
2. 或安装 Markdown Preview Enhanced

### 数学公式

数学公式由 `markdown-it-mathjax3` 在**构建期**渲染成内联 SVG，不依赖任何客户端 JS 或外部 CDN。
VS Code 内置预览也支持 `$$...$$`（走 KaTeX），两边写法一致。

::: details 为什么不再是 KaTeX CDN
早期配置里从 CDN 引了 KaTeX 的 CSS/JS，但那段配置写在 `themeConfig` 里，
而 `head` 是**顶层配置项**——所以它从来没生效过，属于无效配置，已经删掉了。
:::

### 侧边栏里没有新笔记

检查两点：

1. 文件在不在 `sidebar.mjs` 里 `rootDirs` 列出的六个顶级目录之内
   （知识积累 / 考试 / 工作 / 兴趣 / 软件学习 / 其他）
2. 所在目录有没有 `index.md`

## 附：需要单独维护的地方

| 位置 | 说明 |
| --- | --- |
| `docs/.vitepress/theme/style.css` | 配色变量与正文样式，**同时作用于站点和 VS Code 预览** |
| `docs/.vitepress/theme/vscode-preview.css` | 仅 VS Code 预览用，补 VitePress 内置变量 |
| `.vscode/settings.json` | 预览挂载、链接校验、粘贴规则 |
| `.vscode/vitepress.code-snippets` | 代码片段，可自行增删 |
| `docs/.vitepress/config.mjs` | 站点标题、base、导航、搜索、sitemap |

::: tip 双目标样式的原理
`style.css` 里的正文规则统一写成 `:is(.vp-doc, .vscode-body)`：

- `.vp-doc` 是 VitePress 的正文容器
- `.vscode-body` 是 VS Code 预览的正文容器

一份规则同时服务两边，不会出现「改了站点忘了改预览」的漂移。
`.vscode-body` 在站点里不存在，对线上零影响。
:::
